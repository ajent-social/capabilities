# Contributing

Start with a demonstrated repeated problem. Open a proposal describing intent, source evidence you are permitted to publish, semantic differences, existing alternatives, the smallest contract and a real adoption plan.

Use a pull request for implementation changes. Include the capability ID, guarantees and non-goals, security boundaries, dependency rationale, provenance, license review, tests actually run and consumer verification. Preserve product-specific policy. Do not publish private material to justify reuse.

No new capability is stable during its first extraction. Rejection in favor of an existing library is a useful contribution. Changes to security-sensitive APIs require human maintainer review.

Original contributions are licensed under Apache-2.0. Only contribute material you have the right to publish under that license; preserve third-party notices. No contributor license agreement is implied.
